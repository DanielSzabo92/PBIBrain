# Trust boundaries and supported execution

PBIBrain remains read-only toward Power BI sources. New impact/compare API and MCP tools expose no apply, authorize or promotion capability. The Change Guard service binds loopback by default and requires an independent guard session header; Brain session credentials do not work. Browser requests must match the configured origin/host. The authenticated review URL uses a fragment, removes it from history, and sends no referrer. Static review assets contain no controller key.

The supported agent launcher runs only a trusted, already-present digest-pinned Docker image. It mounts the candidate directory alone, disables network and privileged capabilities, uses an unprivileged UID, read-only root, bounded resources and no-new-privileges. Baseline, original sources, controller state, policies, keys, user profile and deployment credentials are excluded. A successful signed receipt is tied to the exact candidate source hash. Missing launcher/runtime proof prevents acceptance. Docker is unavailable in the implementation environment, so actual isolation escape/access testing remains NOT_RUN.

A Git worktree or directory copy alone is not a security boundary. Same-user unrestricted host agents are not a supported guarded execution mode. The controller's OS permissions and Docker host must be administered separately from the coding agent. HMAC protects evidence integrity within this boundary; it does not protect a signing key from a compromised host administrator.

Paths are canonicalized and checked for root escape, traversal, ADS/drive paths, symlinks/reparse points, hardlinks, case aliases, Windows reserved names and trailing dot/space aliases. Dedicated roots contain recognized text metadata and hash-pinned report images/fonts in `StaticResources`. Opaque resources are preserved; changes fail source coverage. Unexpected binaries/executables or protected candidate directories reject. External metadata artifact paths reject. Ignored baseline `.git`, `.pbi`, `.pbibrain` and `.pbi-guard` directories never enter candidates; they cannot be created by an accepted candidate.

Untrusted names, descriptions, annotations, queries, comments, report text and errors are data. They are neither controller instructions nor executable privileged scripts. React renders text as escaped content. No generated code is loaded into the evaluator/promotion process. Recognized credential fields, secret-valued annotations/parameters, and potential literal connection credentials block guarded scanning/copying before source metadata enters audit evidence or candidates. This conservative detector does not replace deployment-specific secret inventories. Raw transport error strings are not retained in regression records.

Contracts and policy are hashed before execution. Every difference must match an authorized operation/property/value. Source coverage is mandatory, even for fields the lightweight parser omits. Baseline/candidate modifications after verification invalidate results and approvals. Required unsupported/static/runtime/coverage evidence blocks regardless of agent or human confidence. Human approval cannot override scope or fundamental source integrity.

Append-only application audit JSONL records are HMAC signed and hash chained. A separate signed head detects removed valid tail records, missing logs and interrupted appends. Signed state, evidence and recovery journals live outside the agent mount. Interrupted audit/head writes fail closed and require trusted inspection; automatic audit repair/retention is not implemented.
